## 1. Core Process Events

### `process_exec` — **[NEW v0.8.0]**

The foundational event capturing process execution. Fields include:

- **Binary path** — full executable path resolved via dentry traversal
- **Arguments** — command-line arguments
- **Environment** — environment variables (requires opt-in; added **v1.7.0**, see §5)
- **Working directory** — current working directory
- **PID / TID** — process and thread IDs
- **Parent PID** — parent process relationship

**Reliability improvements:**
- **[FIX v1.1.0]** — `matchBinaries` selector rework to correctly read the process exe at execve ([#1926](https://github.com/cilium/tetragon/pull/1926), [#1731](https://github.com/cilium/tetragon/pull/1731))
- **[FIX v1.4.0]** — Path truncation fix: dentry path reading extended to 4096 bytes (was 256) ([#3427](https://github.com/cilium/tetragon/pull/3427))
- **[FIX v1.6.0]** — Argument corruption fix for processes with long executable filenames ([#3972](https://github.com/cilium/tetragon/pull/3972))
- **[FIX v1.6.0]** — More robust process argument parsing logic ([#3974](https://github.com/cilium/tetragon/pull/3974))

### `process_exit` — **[NEW v0.8.0]**

Captures process termination. Fields include exit code, signal, and core dump indicator.

**Reliability improvements:**
- **[FIX v1.0.0]** — Exit sensor hooked on `acct_process` for more reliable exit tracking ([#1509](https://github.com/cilium/tetragon/pull/1509))
- **[FIX v1.1.0]** — Detection of `disassociate_ctty` as exit probe when needed ([#1853](https://github.com/cilium/tetragon/pull/1853))
- **[FIX v1.3.0]** — Correct exit signal field when process core-dumped ([#3039](https://github.com/cilium/tetragon/pull/3039))

### `process_kprobe` / `process_tracepoint` / `process_lsm` — **[NEW v0.8.0]**

Events generated by instrumented kernel hooks, carrying:
- Process context (same fields as `process_exec`)
- Hook-specific arguments (kernel function arguments, file paths, network data)
- **`policy_name`** field added **[NEW v1.0.0]** for rule attribution ([#1574](https://github.com/cilium/tetragon/pull/1574))

## 2. Credential & Privilege Telemetry

### UID/GID in `process_exec` — **[NEW v1.0.0]**

**Evidence:** [#1296](https://github.com/cilium/tetragon/pull/1296)

Tetragon adds `uid` and `gid` fields to `process_exec` events, exposing:
- Effective UID/GID at process start
- Detection of processes running as root (uid=0)

**EDR value:** Immediate privileged execution detection without writing a separate detection rule.

### Privileged Execution Detection — **[NEW v1.0.0]**

Detects when a process starts with elevated privileges (root, capabilities).

**Enhancement [v1.1.0]:** Dedicated detection of binary execution that raises process privileges (SUID bit execution, `setuid()` calls, capability acquisition) via ([#1786](https://github.com/cilium/tetragon/pull/1786)).

### Username in Process Events — **[NEW v1.2.0]**

Human-readable username resolved from UID and included in process events. Simplifies alert triage without requiring UID→username lookups in the SIEM.

### `ProcessCredentials` Object & Capability Tracking — **[NEW v0.11.0]**

**Evidence:** [#888](https://github.com/cilium/tetragon/pull/888), [#895](https://github.com/cilium/tetragon/pull/895), [#1189](https://github.com/cilium/tetragon/pull/1189)

Introduced in v0.11.0:
- `ProcessCredentials` object tracking Linux credentials (uid, gid, effective uid/gid, capability sets)
- Monitoring credential changes at syscall level (`setuid`, `setgid`, `capset`, etc.)
- Capability usage recording

**EDR value:** Ground-truth credential state for container/process escape scenarios.

## 3. Process Lineage & Ancestry

### Ancestors in Process Events — **[NEW v1.4.0]**

**Evidence:** [#2938](https://github.com/cilium/tetragon/pull/2938)

Tetragon v1.4.0 adds ancestor process information directly to process events, enabling:
- Full process-tree reconstruction in a single event
- Parent → grandparent → ... chain with binary paths and arguments
- Detection of anomalous spawn chains (e.g., `sshd → bash → curl`)

**Configuration evolution:**

| Release | Change |
|---------|--------|
| v1.4.0 | Per-event-type ancestor flags (`--enable-process-ancestors`, `--enable-process-kprobe-ancestors`, etc.) |
| v1.5.0 | **[DEP]** Per-event flags deprecated; unified `--enable-ancestors` flag introduced ([upgrade note](https://github.com/cilium/tetragon/releases/tag/v1.5.0)) |
| v1.6.0 | **[REM]** Deprecated per-event ancestor flags removed ([#3955](https://github.com/cilium/tetragon/pull/3955)) |

**Reliability fixes:**
- **[FIX v1.4.0]** — `in_init_tree` flag incorrectly set for processes before Tetragon start ([#3338](https://github.com/cilium/tetragon/pull/3338))
- **[FIX v1.5.0]** — `inInitTree` not properly accounting for pre-Tetragon processes ([#3827](https://github.com/cilium/tetragon/pull/3827))

### `matchParentBinaries` Selector — **[NEW v1.7.0]**

**Evidence:** [v1.7.0](https://github.com/cilium/tetragon/releases/tag/v1.7.0)

Allows TracingPolicy rules to trigger only when a process was spawned by a specific parent binary. This enables:
- Rules that match `curl` only when launched from `bash`
- Detection of suspicious spawn chains without post-processing in the SIEM
- Complement to `followChildren` for forward-looking and backward-looking lineage checks

### `followChildren` in `matchBinaries` — **[NEW v1.0.0]**

Tracks not only the matched binary but all its child processes. Useful for monitoring the full process tree rooted at a suspicious binary.

**[FIX v1.3.0]** — Fixed tracking of `matchBinary` children ([#3186](https://github.com/cilium/tetragon/pull/3186))

### Accurate TID/PID handling — **[ENH v1.0.0]**

Improved handling of Thread IDs (TIDs) vs process IDs (PIDs) in `GetProcessCopy()` ([#1256](https://github.com/cilium/tetragon/pull/1256)), reducing false associations in multi-threaded process tracking.

## 4. Anonymous & Fileless Execution

### Anonymous Binary Detection — **[NEW v1.1.0]**

**Evidence:** [#499](https://github.com/cilium/tetragon/pull/499)

Tetragon v1.1.0 adds detection of execution from anonymous (memfd, deleted, or path-unresolvable) binaries. This covers:
- `memfd_create()` + `execveat()` (in-memory execution)
- Execution from a file that has already been deleted (`/proc/self/fd/X`)
- Reflective loading patterns

**EDR value:** Direct visibility into fileless malware and LOLBin-adjacent techniques without relying on filesystem monitoring.

## 5. Environment Variable Retrieval

### Environment Variables in Events — **[NEW v1.7.0]**

**Evidence:** [v1.7.0](https://github.com/cilium/tetragon/releases/tag/v1.7.0)

Tetragon v1.7.0 introduces the ability to capture environment variables from process exec events. This is a **high-value addition** for EDR use cases:

| Detection Use Case | Environment Signal |
|-------------------|--------------------|
| Credential theft | `AWS_ACCESS_KEY_ID`, `KUBECONFIG`, `DOCKER_*` in child processes |
| LOLBin context | `PATH` manipulation, `LD_PRELOAD` injection |
| Container escape indicators | `KUBERNETES_SERVICE_*` access from untrusted processes |
| Lateral movement | Shell variables passed across host boundaries |

**Caveats:**
- Requires opt-in in TracingPolicy (not default-on for all exec events — would be noisy)
- Environment variables are captured at exec time; post-exec mutations are not tracked
- Large environment lists may require tuning

## 6. Container Init Tree Context

### `in_init_tree` Flag — **[NEW v1.3.0]**

**Evidence:** [#3209](https://github.com/cilium/tetragon/pull/3209)

The `in_init_tree` boolean flag in process events indicates whether a process was spawned from its container's init process tree. This enables:
- Distinction between container-managed processes and side-door injections
- Detection of processes that bypassed the container runtime entry point
- `in_init_tree` export filter to scope event streams to init-tree or non-init-tree processes

**Reliability fixes:**
- **[FIX v1.4.0]** — Incorrect flag for processes started before Tetragon ([#3338](https://github.com/cilium/tetragon/pull/3338))
- **[FIX v1.5.0]** — Additional `inInitTree` accounting fix ([#3827](https://github.com/cilium/tetragon/pull/3827))

## 7. Kernel Module Tracking

### Kernel Module Operations — **[NEW v1.0.0]**

**Evidence:** [#1390](https://github.com/cilium/tetragon/pull/1390)

Tetragon can instrument `init_module` / `finit_module` / `delete_module` kernel functions to detect:
- Unauthorized kernel module loading (rootkit staging)
- Module unloading that disables security controls
- Module origin (path, arguments)

**EDR value:** High-signal indicator for rootkit installation or kernel security bypass.

## 10. EDR Design Notes

### Process-Tree Reconstruction

Tetragon alone provides the raw events; process-tree reconstruction requires a **stateful consumer** that:
1. Maintains a PID→process mapping keyed on `(pid, start_time)`
2. Links each `process_exec` to its parent via `parent_pid`
3. Uses the `ancestors` field (v1.4.0+) for context on processes that were already running when Tetragon started

### Blind Spots

- **Processes that pre-date Tetragon startup** — Tetragon scans `/proc` at startup to populate initial process state, but may miss very short-lived processes.
- **PID namespace collisions** — in heavily containerized environments, host PID and namespace PID must both be tracked.
- **Short-lived child processes** — if a child process starts and exits faster than the event cache can correlate parent info, the event may carry incomplete parent data (event cache retries mitigate this).

### Kernel Version Dependencies

- Process exec/exit telemetry: Linux ≥4.9 (basic), ≥5.10 recommended for kprobe multi.
- `fentry` for fast exec hooks: Linux ≥5.5 with BTF.
- `in_init_tree` and ancestor support: no specific kernel constraint beyond baseline.
